## 2. 與計畫不同的地方

| 計畫 | 實際 | 原因 |
| --- | --- | --- |
| AG-UI 用 `AGUI.Abstractions`／`Formatting`／`Server` | 只用 `Abstractions` 與 `Formatting` | 事件來源是 `GroundedAnswerEvent`，不是 `IChatClient` 的串流，`AGUI.Server` 用不到，已移除 |
| 前端 bundle 只有一份 rxjs | 巢狀的 rxjs 已去重（根目錄鎖 7.8.1）；zod 仍有兩份 | 見 #104 |
| 後端 view 省略 null 欄位 | 一律輸出 null，並新增 `OpenApiContract` 契約一致性檢查 | 省略欄位與 OpenAPI 不一致，曾造成 #103 |
| 訊息依 `CreatedAt` 排序 | 改用每個對話串自己的 `Sequence` | 同一時間存入的兩則訊息，順序不固定 |
| 重試時直接重送 | 前端帶 client message id，後端遇到同一個 id 就沿用原本的問題 | #105 |
| `Assistant.MinScore` 可以依助理調整 | 欄位已有，但還沒有修改入口，一律使用部署預設 0.3 | 等真實模型評測校正後再開放 |

## 3. 品質把關

- **`master` 已設保護**（ruleset `Protect master`）：
  - 必須透過 PR 合併；
  - `build`、`e2e`、`e2e-api` 三項檢查都要通過；
  - 禁止 force push 與刪除分支；
  - repo 管理員可以略過。
- **`e2e-api`**：在 CI 起 pgvector、migrate、API（Fake 模型）與 API 模式的前端，跑 `knowledge-api.cy.ts` 與 `chat-api.cy.ts`，約 3 分鐘。已在 CI 做過負向驗證：讓試查回 500 時，job 會失敗。
- **契約**：
  - `OpenApiContract` 會檢查回應是否包含 OpenAPI 標為必填的每個鍵；
  - `tools/agui-contract` 用 `@ag-ui/client` 實際解析後端的 SSE 錄製檔。
- **驗收方式**：每張會改到 API 模式行為的前端票，都在瀏覽器做過手動驗收。M3 期間有兩個 bug 是單元測試、Cypress 全綠，卻由手動驗收抓到：#91 助理存檔時丟掉真實的知識庫，以及 #103。
