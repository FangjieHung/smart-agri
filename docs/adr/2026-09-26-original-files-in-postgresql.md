# ADR｜知識庫原檔存放在 PostgreSQL

**狀態：** 已確認（2026-09-26）

## 決策

- 使用者上傳的知識庫原檔（PDF、DOCX、XLSX、TXT／Markdown）以 `bytea` 存在 PostgreSQL 的獨立資料表（`knowledge_file_contents`），與文件版本一對一。列表與詳情查詢不讀這張表，只有下載原檔與背景解析時才讀。
- 單檔上限預設 20 MB，由設定 `Knowledge:MaxFileBytes` 調整；Kestrel 的請求大小上限與它一致。
- 新增版本時，原檔、版本中繼資料與處理工作在同一個交易內寫入；刪除文件時，原檔、版本、段落與向量在同一個交易內刪除。

## 理由

[PostgreSQL 作為唯一資料庫的 ADR](2026-09-25-postgresql-as-single-store.md) 的出發點，是客戶自行部署時只需維運一個資料庫。原檔也放進同一個資料庫，備份與還原只有一份，不會出現「資料庫還原了但檔案沒還原」的不一致；刪除文件也不會留下孤兒檔。以中小企業知識庫的規模（數百份、單檔數 MB）來看，資料庫的大小可以接受。

## 考慮過的選項

- **掛載磁碟（檔案系統）**：資料庫較小、讀寫較快，但多了一份需要備份的資料，而且檔案與資料列的一致性要自己處理（交易失敗時要清掉檔案，還原時要兩邊對齊）。
- **物件儲存（S3 相容）**：適合大量檔案，但地端部署要多維運一個服務，違背單一資料庫的原則。

## 影響

- 資料庫與備份檔會隨原檔一起成長，部署說明要提醒備份空間。
- 反向代理（如 nginx）的上傳大小限制也要調到 20 MB 以上，否則請求會先被代理擋下。
- 若日後單檔需求明顯超過上限，或原檔總量影響備份時間，再評估改用物件儲存；存取集中在 Infrastructure 的單一介面，替換範圍有限。
