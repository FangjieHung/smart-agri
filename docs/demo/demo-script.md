# 中小企業 AI 助理 Demo：5–10 分鐘展示腳本

適用版本：`apps/admin`（純前端 Demo，無後端、無真實 AI）。
安裝、啟動與限制說明見 [`apps/admin/README.md`](../../apps/admin/README.md)。

- 總長：約 **7 分 20 秒**（8 段，含緩衝可壓在 10 分鐘內）。
- 網址以 `http://localhost:4200` 為例；若 dev-server 改用其他埠，請整份對應替換。
- 整場只需要一個瀏覽器分頁。**不要在任何欄位輸入真實個資。**

---

## 事前準備（展示前 2 分鐘做完）

1. 啟動 dev-server：`npm start`（4200 被佔用時，終端機會問要不要換埠，選 `Yes`，以印出的網址為準）。
2. **清空 Demo 資料**，讓每次展示都從相同的起點開始。打開瀏覽器 DevTools Console，在 `http://localhost:4200` 的分頁執行：

   ```js
   Object.keys(localStorage)
     .filter((k) => k.startsWith('sme-demo:'))
     .forEach((k) => localStorage.removeItem(k));
   sessionStorage.clear();
   location.href = '/';
   ```

   也可以用 DevTools 的 Application → Storage → Local Storage，手動刪掉所有 `sme-demo:` 開頭的 key，再刪掉 Session Storage 的 `demo-session`，然後重新整理。
   （不要按「Clear site data」——那會連外觀設定 `sa.theme` / `sa.paradigm` 一起清掉，畫面會跳回預設主題。）
3. 把瀏覽器視窗調到 **1280px 寬**左右；手機段落再用 DevTools 的裝置模擬切到 **360px**。
4. 開場白先講一句定調：**「這是畫面 Demo，資料是固定的假資料，沒有真實 AI，也不是真的登入。」**

## 第 1 段 — 切換管理者帳號（約 40 秒）

**目標**：說明 Demo 有三種身分，而且身分切換是整場「資料隔離」示範的基礎。

**點擊路徑**

1. 開 `http://localhost:4200/` → 點右上角「進入 Demo」（到 `/login`）。
2. 在「選擇 Demo 身分」點 **「SMB 管理者」** → 自動進到 `/app/home`。

**要講的一句話**
> 「這裡沒有密碼，只是切換三種身分：管理者、內部同仁、外部客戶。等一下我們會回來換身分，看同一個助理在不同帳號眼中長什麼樣子。」

**預期畫面**
`/login` 有三顆身分按鈕，上面寫著「Demo 帳號切換，不是真實驗證」與「閒置超過 30 分鐘後就會結束」。選完進到工作台首頁，左側導覽有：首頁、我的助理、和助理對話、知識庫、資料庫（數據收集）、對話與回報紀錄、發布管道、團隊與設定。首頁列出 2 個可使用的助理，並註明「對話只屬於你的帳號，助理建立者看不到你的提問與回答」。

---

## 第 2 段 — 建立助理（約 80 秒）

**目標**：證明非技術使用者能用四個步驟完成一個可用助理。

**點擊路徑**

1. `/app/home` → 點「建立新助理」（到 `/app/assistants/new/purpose`）。
2. 選模板 **「回答客戶問題」** → 名稱與用途會自動填成「客戶問答助理」。
3. 在「誰會使用這個助理？」勾選 **「外部客戶」**。
4. 點「下一步」→ 進到 `/app/assistants/new/sources`。

**要講的一句話**
> 「模板只是幫你先填好，全部都能改。這裡問的都是『你想完成什麼工作』，沒有一個欄位在問模型或參數。」

**預期畫面**
頂部有四步驟進度（用途／資料來源／回答規則／試問確認）與「已自動儲存 · MM/DD hh:mm」。

**小加分（10 秒，可略）**：先不勾使用對象就按「下一步」，畫面會停在原地、欄位下方出現紅字「請至少選擇一種使用對象。」，焦點自動跳到那個欄位——示範錯誤訊息會說明下一步，而不是把人丟到空白頁。

## 第 3 段 — 混接來源（約 60 秒）

**目標**：示範一個助理可以同時連接多個知識庫與多個資料庫，而且兩種來源混在同一份清單。

**點擊路徑**（在 `/app/assistants/new/sources`）

1. 點「加入 商品使用指南」（知識庫）。
2. 點「加入 退換貨政策」（知識庫）。
3. 點「加入 訂單資料庫」（資料庫）。
4. 點「下一步」→ 到 `/app/assistants/new/rules`。
5. 在回答規則頁，把「助理可以用哪些知識回答？」改成 **「允許補充一般知識」**。
6. 在「要把收集到的資訊寫入哪個資料庫？」選 **「訂單資料庫」**→ 下方會展開必填的「收集目的」，填入例如 `收集訂單問題回報，讓客服追蹤處理進度`。
7. 點「下一步」→ 到 `/app/assistants/new/test`。

**要講的一句話**
> 「知識庫負責『可以引用的內容』，資料庫負責『要收集與比較的紀錄』，兩種可以自由混搭。加入只是建立連接，不會複製或修改原始資料。」

**預期畫面**
清單同時顯示知識庫與資料庫卡片，各有權限、狀態（可使用／處理中／需要處理）與更新時間；上方即時更新成「已連接 2 個知識庫、1 個資料庫」，已加入的按鈕變成「✓ 已連接」。選了寫入資料庫之後，「收集目的」欄位是必填——沒填就不能往下走。

---

## 第 4 段 — 可信回答（約 70 秒）

**目標**：讓觀眾一眼分辨三種回答狀態。

**點擊路徑**（在 `/app/assistants/new/test`）

1. 點「試問：收到商品後幾天內可以申請退貨？」
2. 點「試問：皮革商品平常要怎麼保養？」
3. 點「試問：可以幫我訂下週的機票嗎？」
4. 點「建立助理」→ 跳到 `/app/assistants/<新助理 id>/overview`，顯示「助理已建立」。

**要講的一句話**
> 「同一個助理有三種明確狀態：有公司資料就附上原文與來源；只有一般常識就另外標示、不跟公司資料混寫；兩者都沒有就直接說沒有，並給下一步。」

**預期畫面**
三則回答依序疊在下方：
- **根據你的資料** — 附引用原文「消費者於收受商品後七日內…」與「來源：退換貨政策」。
- **一般知識補充** — 獨立區塊，文末寫「這不是公司資料，僅供參考」。
- **資料中沒有答案** — 顯示你在上一步設定的拒答語「目前的資料中找不到這個問題的答案。請留下聯絡方式…」。

> 📌 **腳本依賴**：`根據你的資料` 這一則需要第 3 段確實加了 **退換貨政策**；`一般知識補充` 需要回答規則設成 **允許補充一般知識**。少做其中一步，對應的回答會變成「資料中沒有答案」。

## 第 5 段 — 同意提交（約 70 秒）

**目標**：示範結構化資料在送出前，一定先揭露接收者、用途與可查看者。

**點擊路徑**

1. 左側導覽點「和助理對話」（`/app/chat`）→ 點 **「客服助理」**（`/app/chat/assistant-customer-service`）。
2. 點建議問題「收到商品後幾天內可以退貨？」→ 回答出現後點 **「查看引用來源（2）」**，看完按「關閉」。
3. 點建議問題 **「我要回報訂單問題」** → 回答下方出現「填寫表單：訂單資料庫」，點它。
4. 填「訂單編號」`DEMO-2026`、「問題類型」選「配送延遲」、「回報日期」選今天 → 點「下一步：確認同意」。
5. 在確認畫面勾選「我已了解上述接收單位與用途…」→ 點「同意並送出」。

**要講的一句話**
> 「送出前一定會先告訴你：資料交給誰、為什麼收、誰看得到，還有一段『別填敏感資料』的提醒。沒有勾同意，送出鍵是關著的。」

**預期畫面**
桌面版在對話視窗左邊有一條「對話紀錄」歷史欄，上方寫「這些對話只保存在你的帳號」。引用抽屜列出兩份文件與原文片段、更新日期。確認畫面依序顯示：接收單位／收集目的／可查看者／敏感資料提示／你填寫的內容／撤回說明。送出後對話中出現「資料已送出」與剛才填的三個欄位。

## 第 6 段 — 帳號隔離（約 70 秒）

**目標**：證明切換帳號後，看不到上一個帳號的任何東西。

**點擊路徑**

1. 網址列直接開 `/login` → 點 **「外部客戶」**。
2. 點左側「和助理對話」（`/app/chat`）→ 點「客服助理」。
3. 依序點左側「我的助理」、「知識庫」、「發布管道」。

**要講的一句話**
> 「同一個助理、同一台電腦，換一個身分之後，剛剛那段對話完全不存在——對話屬於發起對話的帳號，連建立者都看不到內容，只看得到匿名的使用次數。」

**預期畫面**
- `/app/chat/assistant-customer-service`：對話紀錄欄顯示「還沒有任何對話。問第一個問題，就會自動建立一段對話。」——第 5 段那段對話不見了。
- `/app/assistants`：「尚未有可使用的助理」。
- `/app/knowledge`：「還沒有知識庫」。
- `/app/channels`：「目前沒有可設定發布管道的助理／只有助理擁有者可以設定發布管道。」

每個都是有說明的空白狀態，不是錯誤頁、也不是死路。

**（可選，15 秒）對照組**：切回 SMB 管理者後打開 `/app/assistants/assistant-customer-service/activity`，讓觀眾看到建立者這邊只有三個匿名數字（對話次數 19、已解決 12、回饋為有幫助 89%），並寫著「助理建立者看不到使用者的對話內容」。

## 第 7 段 — 追蹤趨勢（約 60 秒）

**目標**：示範資料庫怎麼把多次紀錄變成可比較的結論，以及紀錄不足時不硬掰。

**點擊路徑**

1. 開 `/login` → 切回 **「SMB 管理者」**。
2. 左側「資料庫（數據收集）」→ 點 **「客戶資料庫」** → 上方頁籤點 **「趨勢比較」**（`/app/databases/database-customer-records/trends`）。
3. 在「追蹤對象」下拉選 **「陳先生（1 筆）」**。

**要講的一句話**
> 「本次、上次、首次三欄一起看，差異是系統算好的，AI 只負責把算好的數字講成人話。紀錄不夠的時候，我們寧可不顯示趨勢，也不要給一條會誤導人的線。」

**預期畫面**
- 王小姐（4 筆）：變化摘要「整體滿意度：本次 5 / 5，較上次 +2 分，較首次 +2 分」、「本月消費金額：本次 3,200 元，較上次 +1,100 元」；下方是「首次／上次／本次／較上次／較首次」對照表與兩張折線圖，圖下方各附一份等價的資料表。頁尾註明「差異值由 Demo 資料預先計算；AI 只會把算好的差異轉成文字」。
- 陳先生（1 筆）：改成「紀錄還不夠，暫不顯示趨勢 — 目前只有 1 筆紀錄，累積 2 筆以上才會顯示比較與趨勢。為避免誤導，紀錄不足時不會產生比較結論。」

## 第 8 段 — 官網與 LINE 發布狀態（約 70 秒）

**目標**：示範三個管道各自獨立，一個壞掉不會拖垮其他。

**點擊路徑**

1. 左側「發布管道」（`/app/channels`）。
2. 點客服助理的「官網嵌入 → 查看設定」（`/app/assistants/assistant-customer-service/publishing?channel=website`），切一下預覽的「桌機／手機」，指一下「允許嵌入的網域」與嵌入碼。
3. 點「LINE → 前往處理」（`…/publishing?channel=line`），捲到下方的「逐欄檢查」。

**要講的一句話**
> 「五種狀態是一致的：尚未設定、測試中、已發布、需要處理、已暫停。這個助理的 LINE 權杖失效了，畫面只把 LINE 標成需要處理——官網和平台內照常運作。」

**預期畫面**
`/app/channels` 一次看到三個助理 × 三個管道的狀態矩陣，最上方有「Demo，不會連接外部服務」的提示條。官網頁有桌機／手機預覽、品牌色、顯示位置、網域清單、嵌入碼（指向 `widget.demo.invalid`）與「檢查安裝狀態」。LINE 頁有三步圖文引導、逐欄檢查結果（官方帳號 ID／Channel ID／Channel secret 通過，Channel access token 未通過，並說明「此權杖已失效（模擬結果），請重新發行」）、Webhook 網址與「傳送測試訊息」。

## 加映（時間有餘時各 20–30 秒）

- **官網訪客看到的樣子**：開 `/use/assistant-customer-service?embed=1` — 同一個對話介面，但沒有左側工作台導覽，就是嵌到客戶官網後的模樣。
- **多段對話**：回到 `/app/chat/assistant-customer-service`，點「開新對話」再問一題，歷史欄會出現第二段，可以重新命名或刪除；每段都是獨立的 URL（`/app/chat/<助理>/<對話 id>`），重新整理不會掉。
- **手機版**：把 DevTools 裝置寬度切到 360px，重走第 5 段。左側歷史欄會收合成「對話紀錄（n）」的展開鈕，導覽收成左上角漢堡選單，引用抽屜變成整頁寬。
- **錯誤狀態速覽**：`/app/knowledge/knowledge-product-guide/content` 一頁看完文件的五種處理狀態（可使用／處理中／等待處理／部分內容無法讀取／處理失敗），失敗的那兩份旁邊都有「重新處理」，而且不影響其他四份繼續被引用。

## 若出錯怎麼辦

| 狀況 | 現場怎麼處理 |
| --- | --- |
| 畫面突然跳回 `/login`，寫「Demo 登入已逾時」 | 正常行為：Demo 身分閒置 30 分鐘就結束。重新點一次身分即可，資料都還在（資料存 `localStorage`，逾時只清 `sessionStorage`）。 |
| 試問回答變成「資料中沒有答案」，但你預期是「根據你的資料」 | 第 3 段漏加了 **退換貨政策**。回上一步（`/app/assistants/new/sources`）加進去，再回試問頁重試。 |
| 試問看不到「一般知識補充」 | 回答規則還停在「只依據我的資料回答」。到 `/app/assistants/new/rules` 改成「允許補充一般知識」。 |
| 點「下一步」沒反應 | 一定有必填沒填。畫面會就地顯示紅字並把焦點移到該欄位，往上捲一點就看得到（最常見是「使用對象」與「收集目的」）。 |
| 直接開 `/app/assistants/new/sources` 卻跳回 `/purpose` | 這個帳號目前沒有進行中的草稿（例如上一個草稿已建立成助理）。從第 2 段重新開始即可。 |
| 資料被前一場 Demo 弄亂了 | 執行「事前準備」第 2 步的清除片段，重新整理就回到初始假資料。 |
| 想直接跳到某個錯誤畫面 | 在網址後面加 `?demoScenario=loading` / `partial-failure` / `permission-denied` / `disconnected-channel`。換頁或拿掉參數就恢復正常。 |
| 有人問「這個嵌入碼／LINE 權杖可以直接用嗎？」 | 不行。嵌入碼指向 `widget.demo.invalid`、Webhook 指向 `webhook.demo.invalid`，檢查與測試結果都是寫死的模擬值。 |
| 有人要當場填自己的真實資料 | 請擋下來。所有輸入會以明文存在這台電腦的 `localStorage`，而且這裡的登入與權限都只是畫面模擬。 |
| 在「概覽」「資料來源」「回答與記錄」頁籤改設定後，想按「儲存」卻找不到按鈕 | 這三頁沒有儲存按鈕：每次變更都會自動保存，右上角的狀態列會顯示「已自動儲存」。若顯示的是紅字錯誤（例如清空了助理名稱），代表這一次變更沒有被寫入，把欄位填回去就會恢復。 |
