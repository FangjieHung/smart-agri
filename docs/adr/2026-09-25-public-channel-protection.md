# ADR｜對外管道（網站嵌入、LINE）的防濫用與網域限制

**狀態：** 已確認（2026-09-25）

## 決策

- 以 ASP.NET Core 內建的 Rate Limiter，依訪客、IP 與助理設定頻率限制。
- 每個組織設定每月 token 用量上限；接近上限時通知組織管理者，超過時暫停對外管道的回覆（組織內部使用不受影響）。
- LINE Webhook 一律驗證簽章，驗證失敗直接拒絕。
- 網站嵌入依每個助理設定的允許網域白名單，由伺服器以 CORS 與 `frame-ancestors` 限制；白名單為空時此管道不可用。
- 第一版不加人機驗證（CAPTCHA）。

## 理由

對外管道任何人都能呼叫，濫用會直接變成模型費用。主流人機驗證服務依賴 Google、Cloudflare 等雲端，與完全地端部署衝突，因此先以頻率與用量上限防護，實際遇到濫用再評估。

## 補充（2026-10-06）

[M5a 計畫](../plans/2026-10-06-backend-milestone-5a-website-embed.md)把網站嵌入做成 iframe：對話視窗由 API 在 `/use/{assistantId}` 提供，客戶網站只貼載入器。在這個架構下，「CORS 與 `frame-ancestors`」的分工如下：

- **`frame-ancestors` 決定誰能嵌入**：依助理的允許網域動態產生；助理不存在、未發布或清單為空時一律 `'none'`，回應內容相同。
- **CORS 的用意改由「訪客 API 只接受同源」達成**：widget 與訪客 API 同源，不註冊任何 CORS 政策，帶有其他來源 `Origin` 的請求一律拒絕，外部網站無法在自己的頁面直接呼叫訪客 API。
- 兩者都只在瀏覽器裡有效，擋不住直接以腳本呼叫；真正的防線是頻率限制與用量上限，部署文件要寫明。
- **每月 token 上限**計算組織當月所有對話模型呼叫的輸入＋輸出 token（含組織內部使用，不含嵌入模型）；上限由部署預設值與營運指令設定，組織不能自行修改。用到 80% 時在 admin 提示有 `manage-publishing` 的帳號，超過時只暫停對外回覆。

## 補充（2026-10-06，LINE）

[M5b 計畫](../plans/2026-10-06-backend-milestone-5b-line.md)把同樣的原則套用到 LINE：

- **簽章**：Webhook 對**原始 body** 驗證 `x-line-signature`（HMAC-SHA256、Channel Secret、base64）。助理不存在、沒有 LINE 頻道、Secret 未設定、簽章不符，一律回相同的 `401`。驗證通過後 2 秒內回 `200`，問答在背景處理，並以 `webhookEventId` 去重。LINE 不公布來源 IP，所以不用 IP 白名單。
- **頻率限制**：LINE 的請求都來自 LINE 的伺服器，不能依 IP 分區；改依 LINE 使用者、群組與助理分區。超過時同一個時間窗只提示一次，不呼叫模型。
- **群組**：只在官方帳號被 @ 時回答；逾時不以 push 補送，因為 push 依群組人數計算訊息額度。
- **每月 token 上限**：LINE 的問答計入組織用量；超過時官網與 LINE 一起暫停，組織內部不受影響。
