### 工作方式與環境注意事項

- 在目前的工作目錄開新分支（例如 `docs/m3-plan`），從最新的 `origin/master` 開。文件用繁體中文，commit 用英文 conventional commits。
- 計畫確認後，每張票一個 worktree，派 subagent 實作，我自己驗收：
  - 重跑建置與測試，並讀關鍵程式碼；
  - 推分支、開 PR、等 CI；
  - 只有我說「合併」才合併，用 merge commit。
  - 疊在其他 PR 上的 PR，合併前先 `gh pr edit N --base master`。
- 環境：
  - Node 24：`export PATH=~/.nvm/versions/node/v24.18.0/bin:$PATH`。
  - 後端測試需要 Docker：先看 `sysctl -n vm.swapusage`，再 `colima start --cpu 4 --memory 4`，並設 `DOCKER_HOST=unix://$HOME/.colima/default/docker.sock`、`TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock`。用完 `colima stop`。
  - API 的本機 port 是 5153。
- 已知的坑：
  - PostgreSQL 時間只到微秒，已有 `TimestampPrecisionInterceptor`，測試時鐘多加 7 ticks 來模擬 Linux 的精度。
  - Linux CI 是傳統捲軸。
  - 寫檔工具與 heredoc 會把 `\uXXXX` 轉成真正的字元。
  - 改 UI 入口時，自己在本機跑受影響的 Cypress spec。
- 派工 prompt 必須明文禁止 `git checkout -- .`、`git restore`、`git stash`、`git push`；每條指令以 `cd <絕對路徑> &&` 開頭；禁止 subagent 動 `~/.claude/`。
