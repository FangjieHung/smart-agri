## 4. 這次顯示了什麼（對照 #292）

1. **#292 的第 2 個問題在題庫裡重現了**：地址 0.304、電話 0.343、週二 0.332、公休日 0.313，和實機量到的 0.30–0.39 同一個範圍，而且都低於 0.406。文件是虛構的，所以以後可以在 CI 之外重複量測，不用再拿真實店家的文件。
2. **找得到、但分數太低**：基本資訊表格每題都在前 5 名，所以換更寬鬆的 Top-K 也沒有用。分數低的原因是整節表格只切成一段，問題只對到其中一列。P2（每列一段：「標題＋欄名：值」）要改善的就是這個分數；#292 實機改成每列一段後是 0.375–0.551。
3. **P3 的 `CandidateMinScore` 不能只看店家題**：店家題的最低分 0.304 只比 0.30 高一點，但 0.30 時 8 題應查無結果中有 7 題會進入候選（none-08 0.381、none-09 0.374、none-01 0.379、none-02 0.371、none-05 0.324、none-06 0.323、none-07 0.458）。也就是說，降低門檻之後，要由模型的拒答標記擋下這些題目，所以 P5 要同時看 `eval-answers` 的陷阱題。
4. **P5 比較時看這幾個數字**：store 類別的 hit@1 與命中分數（特別是 store-01～04 能不能 ≥ 0.406）、應查無結果題的最高分（目前 0.458），以及既有 33 題的 hit@5 不能退步。

## 5. 重跑方式

```sh
set -a; . <repo 外的金鑰檔>; set +a
export Ai__Embedding__Provider=OpenAI Ai__Embedding__Model=text-embedding-3-small Retrieval__MinScore=0.406
export ConnectionStrings__Default="Host=localhost;Port=5432;Database=<自己的評測資料庫>;Username=smartagri;Password=smartagri_dev"
dotnet run --project apps/api/src/SmartAgri.Api -- migrate
dotnet run --project apps/api/src/SmartAgri.Api -- eval-retrieval --report "$PWD/docs/evals/<日期>-retrieval-text-embedding-3-small-<票號>.md"
```

`--report` 要給絕對路徑：`dotnet run` 的工作目錄是專案目錄，給相對路徑時報告會寫到 `apps/api/src/SmartAgri.Api/docs/evals/` 底下。
