## ① 判斷中的等待狀態

**顯示條件**：只在伺服器實際進行表單判斷時顯示（Trigger=Model，而且助理有連接表單）。關鍵字模式與沒有表單的助理不顯示，維持現有的「正在回答…」。前端不自行推斷，只依伺服器事件（見 E1）。

**位置與外觀**：
- 放在訊息列表中、使用者訊息下方，靠左，也就是助理泡泡會出現的位置。**不用泡泡、不用三個點、不加圖示**。
- 一行粗體文字，1rem，行高 28px。
- 掃光：文字用漸層填色（`background-clip: text`），`linear-gradient(90deg, #1c2733 0%, #1c2733 35%, #9aa6b2 50%, #1c2733 65%, #1c2733 100%)`，`background-size: 200% 100%`，`background-position` 從 `200%` 到 `-200%`，2.5 秒線性無限循環。
- 文字輪播：四句，每句 1.5 秒，一輪 6 秒。每句由下方 12px 淡入、停留、向上 12px 淡出（進出各約 0.24 秒，不重疊）。
  1. 正在整理問題重點…
  2. 核對相關資訊…
  3. 正在梳理可行做法…
  4. 準備回覆內容…
- 參考效果：kokonutui「AI Text Loading」。app 是 Angular，請用純 CSS（或 Angular animations）實作，**不要引入 React／motion／shadcn**。

**判斷完成後**：等待文字淡出，原位出現「正在回答…」泡泡，或「需要填寫資料」訊息。

**停止**：等待中顯示「停止回答」，行為與現有停止相同（結果文字「已停止回答，這則問題沒有回覆。」）。360px 寬度下，等待／串流中只顯示「停止回答」、隱藏「送出」。

**無障礙**：
- 容器 `role="status"`，內含一段只給螢幕閱讀器的固定文字「助理正在整理你的問題」；四句輪播文字 `aria-hidden="true"`，避免每 1.5 秒播報一次。
- `prefers-reduced-motion: reduce`：不掃光、不輪播，只顯示第一句，顏色 #526170。
- 已知取捨：掃光經過的瞬間，文字對比會短暫低於 4.5:1；資訊由固定的螢幕閱讀器文字承載，負責人已接受。

## ② 表單卡片的退路

範例情境：評測 a07「我想取消剛剛送出的資料」，模型跳出了新表單，但使用者其實想撤回。

**「需要填寫資料」訊息**：在既有標籤「需要填寫資料」與按鈕「填寫表單：{表單名稱}」之間，加一句：

> 我找到一份可能相關的表單。要現在開始填寫嗎？

**表單卡片**：
- 卡片上**不放提示句**。標題列：左邊是表單名稱（h2），**右上只放一個關閉按鈕**（× 圖示、44×44、透明底、圖示色 #526170），`aria-label="關閉表單，不填寫"`。
- 底部按鈕：「下一步：確認同意」（主要）＋「不用了」（次要）。「不用了」**取代現有的「取消」**。360px 下兩個按鈕直排、滿版。
- 底部按鈕下方一行小字（0.875rem，#526170）：「想撤回已送出的資料？」＋連結「前往我送出的資料」（粗體、主色），連到 `/app/activity`。**每次跳出表單都顯示**，不依使用者有沒有資料決定。

**關閉（× 或「不用了」）的行為**：
- 收起卡片，**不送出任何資料**，輸入框維持可用，焦點移到輸入框。
- 原本的「需要填寫資料」訊息改成：「已關閉表單，沒有送出任何資料。」
- 記錄一筆「使用者關閉了模型跳出的表單」事件（只記事件、助理、表單、時間，不記填寫內容），供上線後抽樣檢查誤觸（評測文件第 5 節）。見 E3。

**前往「我送出的資料」**：在同一分頁前往。如果卡片已有輸入內容，先確認「離開會清除已填的內容」；沒有輸入就直接前往。

## ③ 「回報資料」固定入口

**顯示條件**：只在伺服器回報「這位成員在這個助理目前有可用表單」時顯示；清單為空時**整個不出現**（不是停用）。授權規則與 #148 相同，由伺服器決定（見 E2）。

**桌面**：
- 輸入框同一列的最左邊：次要按鈕（白底、主色框與字），左側一個寫字板線條圖示（20px，inline SVG），文字「回報資料」。順序：［回報資料］［輸入框］［送出］。
- 按下後在按鈕上方展開選單（寬約 380px、圓角 12px、浮層陰影）：
  - 標題「選擇要填寫的表單」（0.875rem、粗體、#526170）
  - 每個選項**只列表單名稱**，不顯示說明
  - 底部附註「只列出你目前可以填寫的表單。」
- 鍵盤：選單採 menu 模式，按鈕 `aria-haspopup="menu"`／`aria-expanded`；方向鍵移動、Enter 開啟、Esc 關閉並把焦點還給「回報資料」。

**360px 手機**：
- 「回報資料」放在輸入框上方一列，排在建議問題前面，保留文字標籤（不改成只有圖示）。
- 按下後改為底部面板：遮罩 `rgb(28 39 51 / 40%)`，面板上緣圓角 12px。內容：標題「回報資料」＋右上文字按鈕「關閉」；說明「選擇要填寫的表單。只列出你目前可以填寫的表單。」；選項只列表單名稱（每個至少 56px 高、1px 框線）。面板為 `role="dialog"`、`aria-modal="true"`，焦點鎖在面板內，關閉後還給按鈕。

**行為**：
- 開啟的表單與對話中跳出的是**同一個卡片元件**，同樣有 ② 的關閉按鈕與撤回連結。
- 只有一份可用表單時，按下直接開啟卡片，不出現選單。
- 從入口開表單**不另外在對話紀錄留訊息**。
- 已經有表單卡片打開時再按入口：捲動到已開啟的卡片並把焦點移進去。

## E. 需要的 API 變更

依議題驗收條件，契約要記錄在 M4 設計文件並更新 `openapi/v1.json`。

- **E1 等待事件**：串流回應在進行表單判斷前，先送一個「正在判斷表單」事件；前端收到才顯示 ①，收到第一段回答或表單請求時收起。關鍵字模式與沒有表單的助理不送。模型呼叫失敗退回關鍵字時，同樣在退回後收起。
- **E2 可用表單清單**：「這位成員在這個助理目前可用的表單」清單（id、名稱即可）。授權規則與 #148 相同。空清單 → 不顯示入口。
- **E3 關閉事件**：記錄 ② 的關閉事件（不含填寫內容）。撤回連結每次都顯示，不需要額外查詢。

## 驗收對照（議題 #171）

- 等待狀態只在伺服器實際判斷時顯示：E1。關鍵字模式與無表單助理各補一條測試，確認不顯示。
- 「不用了」不送出資料、可繼續對話；撤回可一鍵前往 `/app/activity`：②。
- 固定入口只顯示伺服器回傳的可用表單，無表單時不出現：③＋E2。
- 鍵盤與螢幕閱讀器可完成三個流程，沿用 `accessibility.cy.ts` 的檢查方式；mock 與 API 模式的 Cypress 都要涵蓋。
- 「取消」改名為「不用了」會影響既有 Cypress／jest 對「取消」的選取，實作時用舊字串掃 `apps/admin` 與 `apps/*-e2e`。
