# ADR｜LLM 供應商、模型來源與資料落地

**狀態：** 已確認（2026-09-25）

## 決策

- 模型供應商由每個部署以設定選擇，程式碼只依賴 `IChatClient`／`IEmbeddingGenerator`。組織只能從部署提供的清單中挑選對話模型；嵌入模型每個部署只有一個（2026-10-06 修正，原寫「由每個部署（及組織）以設定選擇」，見補充（2026-10-06））。
- 預設支援三種來源：
  - Azure OpenAI／OpenAI（官方 SDK）。
  - Anthropic Claude（官方 NuGet 套件 `Anthropic` v10 以上；不得使用同名舊版或社群套件 `Anthropic.SDK`）。
  - 本地模型：以 vLLM 等 OpenAI 相容 API 部署，經官方 OpenAI 用戶端呼叫，不引入社群維護的 Ollama 套件。
- 「非中國團隊」適用於框架與依賴套件。中國團隊開發的模型（Qwen、DeepSeek 等）不列為預設選項，也不隨產品提供；客戶可自行以 OpenAI 相容端點接入並自負責任。
- 必須保留「全地端」路徑：本地模型加自架向量庫，資料不離開客戶環境。
- 每次模型呼叫都留下可稽核的紀錄（組織、帳號、助理、模型、時間、token 用量），不保存呼叫內容（2026-10-06 修正，原寫「內容是否一併保存由組織設定決定」，見補充（2026-10-06））。

## 理由

預期客戶包含農會、合作社與政府相關單位，可能有個資法、資料不得出境或禁用陸製產品的要求。同一份產品既要能用雲端最新模型，也要能在封閉環境運作，因此模型來源必須是設定而不是程式碼。

Gemini 與 Ollama 在 .NET 端目前只有社群維護的套件，不符長期維護要求；vLLM 暴露 OpenAI 相容 API，可沿用官方用戶端。

## 影響

- 部署設定指定嵌入模型與可用的對話模型清單；組織在後台只選對話模型。換嵌入模型需重建向量索引（2026-10-06 修正，原寫「依部署或組織指定模型與嵌入模型」）。
- 助理「只用組織資料」的限制需在檢索與提示組裝時由服務端強制，不能只靠模型遵守指示。

## 補充（2026-10-06）

負責人 2026-10-06 決定 M6「組織設定」中模型選擇的範圍。

**組織只能選對話模型**

- 每個組織只能選對話模型。嵌入模型維持每個部署一個。
- 理由：換嵌入模型要重建該組織整個知識庫的索引；「目前使用的嵌入模型」與「過期段落」的檢查也都是部署層級。
- 以組織為單位選擇，不是以助理為單位。之後需要時，再加助理層級的覆寫。

**可選的模型由部署提供**

- 部署營運者在部署設定中列出可用的對話模型清單：供應商、模型、金鑰與相關設定。
- 組織管理員從清單中挑一個。沒有挑選的組織使用部署預設值。
- 清單只有一個模型時，設定畫面只顯示「目前使用：X」，沒有選單。
- 營運者把組織正在用的模型從清單移除時，該組織改用部署預設值，設定畫面顯示提示。
- 組織自備金鑰（BYO）延後。它牽涉每月 token 上限、計費與金鑰失效的處理；而且由部署控管供應商，比較容易保證資料落地。

**所有對話模型用途都用組織的模型**

- 回答、對外回答、試問與題組重跑、定期報表摘要、表單請求的觸發判斷等，全部使用組織選的模型。
- 這樣驗收測到的，就是上線後實際使用的模型。

**換模型**

- 只有組織管理員能更換。新對話立即生效。
- 每次更換都寫入活動紀錄：誰、何時、換成哪個模型。
- 換模型不影響已發布的助理。助理頁面顯示「上次測試使用模型 X，現在是 Y」，並建議重跑題組。
- 不採用「換模型後強制重新驗收」：那會讓官網與 LINE 上的助理直接下線。

**用量上限**

- 每月 token 上限仍以原始 token 數計算，不依模型價格加權。
- 營運者以「清單裡放哪些模型」控制成本。之後需要時再考慮加權。

**不保存模型呼叫內容**

- 模型呼叫的內容一律不保存，取代原本「由組織設定決定」的寫法。
- 除錯依靠 OpenTelemetry 的 span，以及不含內容的 `ModelInvocation` 紀錄。
- 理由：保存呼叫內容等於把對話完整複製一份，對話保存期限與撤回就形同失效。
