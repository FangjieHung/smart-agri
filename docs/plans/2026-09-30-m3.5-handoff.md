### 合併第二張 PR 的步驟

#136 就是這樣處理的：

1. 在該 worktree 執行 `git fetch && git merge --no-ff origin/master`。
2. `Program.cs` 衝突時，兩邊的 `Map…Endpoints()` 都保留。
3. `openapi/v1.json`、`api-schema.ts`、`AppDbContextModelSnapshot.cs` 先取 master 的版本：`git checkout origin/master -- <檔>`。
4. 用 `git rm` 刪掉這張 PR 自己的 migration 兩個檔案，再用 `dotnet tool run dotnet-ef migrations add <同名>` 重新產生。產生後，比對新的 `Up`／`Down` 應該和原本一樣。
5. 執行 `dotnet build`，build 會重新產生 openapi；成功後，再用 Node 24 跑 `npx nx run admin:api-types`。
6. build 成功後才跑全部測試，再跑 `has-pending-model-changes`。
7. commit 並 push，等 CI 綠燈後合併。

### 工作方式（照舊）

- **一張票一個 worktree**，放在 `butterfish/.worktrees/`，node_modules 用 `cp -cR` 從既有 worktree 複製。
- **派 subagent 實作，我自己驗收：**
  - build 成功才跑測試，以結束碼判斷；不要用 `--no-build` 跑舊的程式，也不要拿 grep 當閘門。
  - 前端另外跑 `tsc -p apps/admin/tsconfig.spec.json --noEmit`（#139 修好前的判斷方式見上）。
  - 會改到 API 模式行為的前端票，要在瀏覽器做 API 模式手動驗收。
- 推送、開 PR、等 CI；只有負責人說「合併」才合併，用 merge commit。

### 已知的坑

- **後端測試會解析前端的 `demo-seed.ts`**（`RetrievalEvalSetTests`）。
- **Hybrid 測試至少要有一條 fixture 直接用 API 實際回應的 JSON 字串**，不要照型別手寫。
- **Fake 嵌入是字元雜湊，不懂語意。** 問句要和文件文字大量重疊，分數才會超過 0.3，例如「收到商品後七天內可申請退貨」約 0.44。
- **列舉完整清單的既有測試**，新增列舉值時要一起更新：`ModelInvocationTests`、`JobOptionsTests`、`AccountWireNameTests`、`OrganizationModelTests`。
- **新增帳號權限時，Cypress 也寫死了權限勾選框的數量**：`accessibility.cy.ts`、`responsive.cy.ts` 都寫 `.member__editor input[type="checkbox"]` 的個數。#140 因為這個原因 CI 變紅；後端或前端票只要加權限，就要一起改這兩支並在本機跑。
- **PostgreSQL 時間只到微秒**；測試時鐘多加 7 ticks。
- **Linux CI 是傳統捲軸。**
- **寫檔工具和 heredoc 會把 `\uXXXX` 轉成真正的字元。**
