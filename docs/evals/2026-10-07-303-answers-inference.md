## 1. 改了什麼

回答規則第 3 條（拒答）原文保留，在它後面加上第 4 條，原本的第 4、5 條順延為第 5、6 條：

> 3. 參考段落不足以回答問題時，只輸出 {拒答標記}，不要輸出任何其他文字。
> 4. 段落寫明了規則或條件（例如期限、營業日與公休日、價格、有沒有供應）時，可以把它套用到使用者描述的情況，直接給出明確的結論，包括否定的結論（例如「已超過七天，無法退貨」「週三公休，當天不營業」），並標註依據的段落；這不算第 3 條的「不足以回答」。只能套用段落寫明的內容，段落沒有寫到的條件、費用或例外，仍依第 3 條處理。

- 第 4 條放在第 3 條後面，並明確寫「這不算第 3 條的『不足以回答』」。#300 基準顯示，條件題被拒答的原因是模型每次對「足不足以回答」的判斷不同，所以要直接說明這種情況不算。
- 最後一句把「段落沒寫到的條件、費用或例外」拉回第 3 條，防止模型用相近的段落推論出退貨運費、外送費這類陷阱題的答案。
- 規則文字裡沒有半形方括號加數字（`Fake` 對話模型用 `[k]` 計算段落數），單元測試有檢查這一點。
- 只試了這一版文字。第一版就達到驗收標準（§2），補充測試也沒有發現漏答（§3），所以沒有再試其他版本。

## 3. 補充：`MinScore` 0.30 下的壓力測試（模擬 P3 之後）

正式評測中，store-01～05 與 trap-01、trap-02 都被門檻擋下，沒有測到第 4 條。為了先看看「這些題送到模型手上會怎麼回答」，另外把 `Retrieval__MinScore` 設成 0.30（接近 #302 預定的 `CandidateMinScore`），新舊提示各跑 3 次。這樣送給模型的段落比較多、比較雜，對陷阱題來說更嚴格。這 6 份報告沒有 commit，只記錄在這裡。它們不是 #302 的設計（#302 是兩段門檻，不是直接降低 `MinScore`），只能當作參考。

## 4. 量測方式

```sh

docker exec smartagri-dev-postgres-1 psql -U smartagri -d smartagri -c "create database p4_303"
docker exec smartagri-dev-postgres-1 psql -U smartagri -d p4_303 -c "create extension vector"

export Ai__Chat__Model=gpt-6-luna Ai__Chat__ReasoningEffort=None
export Ai__Embedding__Provider=OpenAI Ai__Embedding__Model=text-embedding-3-small Retrieval__MinScore=0.406
export ConnectionStrings__Default="Host=localhost;Port=5432;Database=p4_303;Username=smartagri;Password=smartagri_dev"
dotnet run --project apps/api/src/SmartAgri.Api -- migrate
dotnet run --project apps/api/src/SmartAgri.Api -- eval-answers --report "$PWD/docs/evals/2026-10-07-answers-gpt-6-luna-303-run1.md"   # 跑 3 次
```
