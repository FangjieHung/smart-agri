### 工作方式（照舊）

- **一張票一個 worktree**，放在 `butterfish/.worktrees/`。新的 worktree 先跑 `npm ci`，或從最新的 worktree 用 `cp -cR` 複製 node_modules。
- **派 subagent 實作，我自己驗收：**
  - 先 build 成功，才跑測試，並以結束碼判斷結果。不要用 `--no-build` 跑舊的程式，也不要用 grep 當閘門。
  - 前端要另外跑 `tsc -p apps/admin/tsconfig.spec.json --noEmit`；production build 不會編譯測試檔。
  - 改到 API 模式行為的前端票，要在瀏覽器做 API 模式手動驗收。M3 有兩個 bug 是單元測試和 Cypress 全綠，只有手動驗收抓到。
- **推送分支、開 PR、等 CI。** 只有負責人說「合併」才合併，用 merge commit。後合併的 PR 要先併入最新 master、重跑測試。
- **派工 prompt 的規定：**
  - 明文禁止 `git checkout -- .`、`git restore`、`git stash`、`git push`；
  - 每條指令以 `cd <絕對路徑> &&` 開頭；
  - 禁止 subagent 動 `~/.claude/`；
  - 起 dev server 或 Cypress 前，先看 `sysctl -n vm.swapusage`。

### 環境

- Node 24：`export PATH=~/.nvm/versions/node/v24.18.0/bin:$PATH`。
- 後端測試需要 Docker：
  - 先 `colima start --cpu 4 --memory 4`；
  - 設 `DOCKER_HOST=unix://$HOME/.colima/default/docker.sock`、`TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock`；
  - 用完 `colima stop`。
- 本機 API 模式：
  - 用 `deploy/docker-compose.dev.yml`；
  - migrate 時帶 `SEED_DEMO_PASSWORD`、`SEED_DEMO_KNOWLEDGE=true`；
  - API 跑在 port 5153、前端 `nx serve admin --configuration=api` 跑在 4200；
  - 平行驗收時改用 5163 與 4210，做法見 `apps/admin-e2e/README.md`。

### 已知的坑

- **後端測試會解析前端的 `demo-seed.ts`**（`RetrievalEvalSetTests`）。動到這個檔案的前端票，要一起跑那支後端測試。
- **Hybrid 測試至少要有一條 fixture 直接用 API 實際回應的 JSON 字串**，不要照型別手寫。#103 就是這樣漏掉的。
- **Fake 嵌入是字元雜湊，不懂語意。** 問句要和文件文字大量重疊，分數才會超過 0.3，例如「收到商品後七天內可申請退貨」約 0.44。`#fail-midway` 這類 Fake 指令，要接在這種長句後面才會真的觸發。
- **PostgreSQL 時間只到微秒**；測試時鐘多加 7 ticks。
- **Linux CI 是傳統捲軸。**
- **寫檔工具和 heredoc 會把 `\uXXXX` 轉成真正的字元。**
