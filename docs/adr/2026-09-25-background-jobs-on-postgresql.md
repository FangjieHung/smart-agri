# ADR｜背景工作用 PostgreSQL 佇列，不用 Hangfire

**狀態：** 已確認（2026-09-25）

## 決策

文件處理（排隊中 → 處理中 → 完成／部分可讀／失敗）與定期報表等背景工作，以 PostgreSQL 資料表當佇列（`FOR UPDATE SKIP LOCKED` 取件），由 .NET 內建的背景服務（`BackgroundService`）執行；重試次數、下次執行時間與錯誤訊息都記在同一張資料表。不引入排程套件。

## 理由

目前只有兩類背景工作，不值得多一套服務或依賴。佇列與業務資料同一個資料庫，文件狀態與工作狀態可在同一個交易內更新；客戶自行部署時也不多一個要維運的元件。

## 考慮過的選項

- **Hangfire**：最常見，但核心為 LGPL-3.0、進階功能需付費，不符寬鬆授權原則。
- **Quartz.NET**（Apache-2.0）：偏重定時排程，當工作佇列使用較笨重。

## 影響

- 若日後背景工作種類與量大幅增加，再評估專用的佇列服務。
